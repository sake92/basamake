# Architectural Specification: Multi-BSP LSP Indexer & SemanticDB Unification

## 1. Overview & Core Philosophy

This specification details the design of a Language Server Protocol (LSP) navigation index capable of:
1. Supporting multiple concurrent Build Server Protocol (BSP) connections ("worlds").
2. Unifying compiled code references (SemanticDB) with raw parsed sources from Maven dependencies (via Scalameta & JavaParser).
3. Using **SemanticDB Symbol Format** as the universal currency (canonical key) across all lookup tables.

---

## 2. World Isolation Architecture (Multi-BSP Connections)

To support multiple BSP connections simultaneously without key collisions (e.g., different projects using different versions of the same dependency), the global index uses a routing layer:

```scala
class GlobalLspIndex {
  // Maps file URIs to their corresponding BSP project context
  // Key: Document URI (e.g., "file:///path/to/projectA/src/Main.scala")
  // Value: World ID (e.g., "projectA")
  private val fileToWorld: ConcurrentHashMap[String, String] = ...

  // Isolated index per BSP connection
  private val worlds: ConcurrentHashMap[String, BspWorldIndex] = ...
}
```


## Inner World Index Structure
Each BspWorldIndex maintains three primary lookup maps:


```scala
class BspWorldIndex {
  // 1. Cursor Resolution (Position -> Symbol)
  // Maps line/column positions in a file to a SemanticDB symbol string
  val symbolAtPosition: Map[DocumentUri, IntervalTree[SemanticDbSymbol]]

  // 2. Go to Definition (Symbol -> Location)
  // Maps a SemanticDB symbol to its definition site
  val definitionOf: Map[SemanticDbSymbol, Location]

  // 3. Find References (Symbol -> List[Location])
  // Maps a SemanticDB symbol to all its usage locations
  val referencesOf: Map[SemanticDbSymbol, Seq[Location]]
}
```


## 3. Canonical Keys: SemanticDB Symbol Format

All components (SemanticDB files, JavaParser, Scalameta) must map their AST declarations to exact SemanticDB symbol strings.

### Naming Conventions & Suffixes
- Packages: End with `/` (e.g., `scala/` or `com/example/`)
- Classes / Types / Traits: End with `#` (e.g., `scala/Int#` or `com/example/MyClass#`)
- Terms / Methods / Fields: End with `.` (e.g., `com/example/MyClass#method().`)
- Constructors: Represented by `<init>` (e.g., `com/example/MyClass#<init>().`)
- Local Variables: Represented as `local0`, `local1`, etc.

### Key Examples

| Entity Type           | SemanticDB Symbol (Canonical Key)     | Description
|-----------------------|---------------------------------------|--------------------------|
| Package               | com/example/mypackage/                | Package namespace
| Class                 |com/example/mypackage/MyClass#         | Type declaration 
| Method (No Args)      | com/example/mypackage/MyClass#myMethod(). | Term ending in ().
| Overloaded Method     | com/example/mypackage/MyClass#myMethod(+1). | Disambiguated by lexical index.
| Java Standard Method  | java/util/List#size(). |          Java elements follow the exact same syntax.



## 4. AST Transformation for Maven Source Dependencies
When indexing .jar source files from Maven dependencies 
(which lack pre-compiled SemanticDB files), JavaParser (for Java) and Scalameta (for Scala) 
parse the raw source code and programmatically construct SemanticDB symbols.

### Disambiguating Overloads (Lexical Order Algorithm)
SemanticDB **does not require compiler type resolution** to resolve method overloads. It uses **lexical ordering** (textual position in code).

1. The first method named foo in a class gets descriptor foo().
2. The second method named foo in the same class gets foo(+1).
3. The third gets foo(+2)., and so on.

```scala
case class AstMethod(name: String, line: Int, location: Location)
case class AstClass(name: String, packagePath: String, methods: Seq[AstMethod])

def indexClassMethods(clazz: AstClass): Unit = {
  val ownerPrefix = s"${clazz.packagePath}/${clazz.name}#"

  // Group methods by name and sort by line number
  clazz.methods.groupBy(_.name).foreach { case (methodName, overloads) =>
    val sortedOverloads = overloads.sortBy(_.line)

    sortedOverloads.zipWithIndex.foreach { case (method, index) =>
      val disambiguator = if (index == 0) "()" else s"(+${index})"
      val symbol = s"${ownerPrefix}${methodName}${disambiguator}."

      // Store directly in definition index
      definitionOf.put(symbol, method.location)
    }
  }
}
```

### Critical Edge Cases

Constructors (<init>): Java constructor names must be explicitly renamed from the class name to <init>. Overloads follow the same sequence (`<init>().`, `<init>(+1).`).

**Static vs. Instance Methods**: Static and instance methods share the same overload counter within a class.

Class Inheritance: The overload disambiguation counter resets for every class declaration. Method overrides in subclasses generate symbols under the subclass owner prefix (e.g., `SubClass#method().`), eliminating the need to traverse hierarchy trees during symbol generation.

## 5. Secondary Consideration: Memory Optimization
If memory footprint becomes a constraint during large-scale indexing:

Symbol Table Interning: Map string symbols to 32-bit integers (SymbolID: Int).

Bit-Packed Range: Pack startLine, startCol, endLine, endCol into a single 64-bit primitive Long.

Primitive Collections: Use fastutil / Koloboke Int2LongOpenHashMap structures to avoid JVM object wrappers.

Owner Decomposition: Store parent prefixes (OwnerID) hierarchically to eliminate duplicate package string storage.
